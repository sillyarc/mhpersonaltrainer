1. Resumo Executivo

O produto e um ecossistema unico com duas interfaces principais: web-next e mh-personal-trainer-react-native. As duas apps usam o mesmo backend (Firebase + servicos auxiliares), entao dados de treino, avaliacao, perfil, assinatura e notificacao se cruzam entre plataformas.

Mapa de operacao principal solicitado:
Personal: WebNext + React Native
Academia: WebNext
Aluno: React Native (com acesso web limitado)
Admin: WebNext (com suporte mobile secundario)

2. Como os Apps se Juntam

[WebNext] --------------------\
                               > [Firebase Auth + Firestore + Storage] --- [Cloud Functions + Stripe + IA]
[React Native/Expo] ----------/

Ambos os frontends leem/escrevem nos mesmos documentos de usuarios e modulos de negocio.
Nao sao dois sistemas separados: sao duas "faces" do mesmo produto.

4. Auth e Role Resolution

4.1 WebNext

  • Auth central em web-next/lib/auth.tsx.
  • Role suportadas no web: aluno, personal, professor, academy, admin.
  • Rotas protegidas por AuthGate e gates especificos (AdminGate, AcademyGate).
  • No web, aluno e propositalmente limitado a viewport pequena (regra no AuthGate).

4.2 React Native

  • Auth principal em mh-personal-trainer-react-native/src/hooks/useAuth.ts + store em src/store/authStore.ts.
  • Role no mobile: admin, professor, aluno.
  • Fluxo inicial: splash (app/index.tsx) decide /(auth)/login ou /(tabs).
  • Firebase inicializa em src/services/firebase.ts com persistencia e fallback por plataforma.

5. Arquitetura de Dados Compartilhados

  • Documento base do usuario: users/{uid} (nome, papel, assinatura, codigos, metadados).
  • Subcolecoes e colecoes de dominio para treinos, avaliacoes, agenda, notificacoes e financeiro.
  • Relacao personal-aluno por codigoPersonal e referencias no usuario/aluno.
  • Relacao academia por codigoAcademia e flags de vinculo.
  • Servicos de leitura/escrita paralelos em web e mobile (arquivos firestoreService.ts em ambos os projetos).

6. Fluxos Integrados por Papel

Personal cria treino no Web -> Aluno executa no Mobile

  • Personal/professor autenticado no WebNext cria rotina em rotas de treino.
  • Dados sao salvos no Firestore (subcolecoes de usuario, como createTreinos).
  • Aluno faz login no React Native e carrega os treinos vinculados no mesmo backend.
  • Conclusoes do aluno atualizam campos de progresso/ultimo treino.
  • Painel do personal (web) consegue refletir status e evolucao.

Academia gerencia vinculacoes no Web

  • Conta com academyAccount usa rotas /academy/*.
  • Academia vincula alunos e personais por codigos e metadados no Firestore.
  • Esse vinculo impacta quais dados aparecem para personal e aluno nos apps.

Aluno principal no React Native

  • Aluno entra por /(auth)/login e segue para /(tabs).
  • Tela inicial, treinos, avaliacoes, financeiro e chat leem os mesmos documentos do Firebase.
  • No WebNext, aluno existe, mas o acesso no browser e propositalmente limitado para viewport menor.

Admin opera no WebNext

  • Admin (papel admin) acessa rotas /admin/* e monitora usuarios/suporte.
  • Cloud Functions e notificacoes de seguranca alimentam o painel admin.
  • Existe suporte administrativo no mobile, mas o centro operacional principal esta no WebNext.

8. Integracao de IA, Pagamentos e Notificacoes

8.1 IA (OpenRouter)

  • Web: web-next/lib/services/ai.ts.
  • Mobile: mh-personal-trainer-react-native/src/services/ai.ts.
  • Ambos usam modelo/endpoint configuravel por variaveis de ambiente.
  • Controle de creditos diarios para plano gratuito com bypass para premium.

8.2 Pagamentos (Stripe + Functions)

  • Web: web-next/lib/services/payments.ts.
  • Mobile: mh-personal-trainer-react-native/src/services/payments.ts.
  • Fluxos usam endpoints de Cloud Functions (createInscricao, createSetupIntent, createCheckoutSession, etc.).
  • Dados de assinatura refletem no documento de usuario e impactam IA/limites.

8.3 Notificacoes

  • Mobile registra token e envia para users/{uid} (fcm_tokens, pushToken).
  • Web tambem escreve token (fallback web) e gerencia alertas locais.
  • Colecao notificacao e compartilhada para feed e alertas de seguranca.
  • Cloud Functions em firebase/functions/index.js tratam dispatch de push em escala.

9. O que isso significa na pratica

  • Nao ha separacao de produto por plataforma. Existe um unico dominio de negocio e dois clientes.
  • Personal e o elo cross-platform. Pode operar no web e no app sem duplicar conta ou dados.
  • Academia e governanca via web. Organiza vinculacoes e operacao institucional.
  • Aluno e experiencia nativa. Consumo diario de treino/progresso no mobile.
  • Admin e controle central no web. Visao global, suporte, seguranca e operacao.
